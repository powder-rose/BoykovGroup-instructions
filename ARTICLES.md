# Статьи с инструкциями

Администратор открывает вкладку **Статьи** на главной странице. В списке доступны поиск, фильтр по статусу, создание, редактирование и удаление. Публичный раздел — `/stati`, отдельная статья — `/stati/{slug}`.

## Работа в редакторе

1. Укажите заголовок и при необходимости адрес статьи. Пустой адрес создаётся из заголовка.
2. Пишите текст в редакторе: доступны H2/H3, списки, ссылки, таблицы и врезки.
3. Установите курсор в место вставки и нажмите **+ Инструкция**. Вставьте название и полный текст. После блока можно продолжать статью.
4. Используйте **Предпросмотр**, затем сохраните черновик или заполните SEO Title/Description и нажмите **Опубликовать**.

Можно вставить несколько инструкций. Кнопка PDF всегда находится под соответствующим текстом. PDF содержит именно текст этого блока: импортёр каталожных инструкций не используется и приложения не удаляются. Инструкция из статьи не создаёт отдельную запись каталога.

Гость при нажатии PDF открывает существующую регистрацию. Пользователь должен подтвердить e-mail; администратору скачивание также доступно. Проверка выполняется на сервере общей middleware с каталожным PDF. Успешные скачивания обычных пользователей учитываются в существующей статистике.

Локальные черновики разделены по администратору и статье. Восстановление предлагается явно. Изменение статьи в другой вкладке обнаруживается по `revision`: устаревшая версия не перезапишет новую. Сохранение опубликованной статьи обновляет её публичную версию, а **Снять с публикации** закрывает страницу, API и PDF.

## Хранение и API

Статьи сохраняются атомарно в `server/src/data/articles.json`. Этот runtime-файл исключён из Git и попадает в существующий mount и резервное копирование `server/src/data`. Изменения схемы каталога и миграция текущих инструкций не нужны.

Контент — проверяемое дерево JSON Tiptap с разрешёнными типами узлов и ссылок. Произвольный HTML, скрипты и изображения не сохраняются как разметка. Лимит текста статьи — 500 000 символов, HTTP-запроса административных статей — 2 МБ.

| API                                                 | Доступ                                                               |
| --------------------------------------------------- | -------------------------------------------------------------------- |
| `GET/POST /api/admin/articles`                      | Администратор                                                        |
| `GET/PUT/DELETE /api/admin/articles/:id`            | Администратор; PUT/DELETE требуют `revision`                         |
| `GET /api/articles`                                 | Список опубликованных статей без полного контента                    |
| `GET /api/articles/:slug`                           | Только опубликованная статья                                         |
| `GET /api/articles/:slug/instructions/:blockId/pdf` | Подтверждённый пользователь или администратор, опубликованная статья |

Публичные страницы содержат полный текст в серверном HTML, canonical и JSON-LD. В sitemap попадают только опубликованные статьи. Черновики и отсутствующие адреса возвращают HTTP 404.

## Проверка и выпуск

`npm run quality:check` проверяет форматирование, ESLint, конфигурацию ESLint, серверные сценарии и сборку клиента. Тесты статей покрывают CRUD, права, черновики, конфликты версий, атомарную запись, опасную разметку, полный текст настоящего PDF и серверный HTML.

Для выпуска нужны **обновление frontend и пересборка API**. После установки зависимостей `npm ci --prefix client` выполните `npm run build:client` и перенесите содержимое `client/dist` в используемый production-каталог `public_html` штатным способом, сохранив размещённые там статические документы. Затем пересоберите и пересоздайте сервис API через Compose. Новый редактор загружается отдельным клиентским модулем только для администратора.

Production Compose уже передаёт неизвестные публичные пути backend через `@backend`; отдельное правило nginx для `/stati` не требуется.
