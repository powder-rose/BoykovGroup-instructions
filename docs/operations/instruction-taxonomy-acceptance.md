# Приёмка структуры инструкций

Проверка выполняется на неизменяемой копии актуальных данных. Она формирует перечни URL,
SEO-настроек, ссылок и редиректов; при наличии исходной копии сравнивает сохранность инструкций.
Отдельный режим HTTP сверяет работающий сайт с переданным снимком. Команда не импортирует CSV,
не назначает разделы и теги, не публикует страницы и не исправляет обнаруженные замечания.

## Что подготовить

- Снимок каталога опубликованных инструкций `server/src/data/instructions`.
- Точную копию рабочего реестра `server/data/instruction-taxonomy.json`, если он уже создан.
  Если реестр ещё не инициализирован, явно используйте исходный seed без `--registry`.
- При проверке сохранности — снимок инструкций до внедрения, сохранённый отдельно.
- Для HTTP — адрес работающего тестового сайта с данными, соответствующими снимку.

Снимайте данные согласованно, вне параллельной записи и незавершённых массовых операций.
Не запускайте проверку изменяемой рабочей папки как замену согласованному снимку.
Реестр, инструкции, черновики и журнал массовых операций должны относиться к одному состоянию.
Проверка опубликованного снимка не доказывает сохранность черновиков, двоичных файлов скачивания
или всей резервной копии.

Production Compose читает данные из смонтированных каталогов хоста:
`app/server/src/data` → `/app/src/data`, `app/server/data` → `/app/data`,
`app/server/uploads` → `/app/uploads`. Получайте актуальные данные из этих источников,
а не из слоя образа Docker. Реально смонтированный Nginx-конфиг находится в `nginx/default.conf`
относительно production Compose; копия конфига только в репозитории не подтверждает его применение.

## Запуск в Windows PowerShell

Откройте терминал WebStorm в корне проекта. Подставьте собственные пути. Папка отчётов должна
быть новой и находиться вне снимков и каталога реестра; родительская папка должна существовать.

```powershell
$snapshotPath = 'C:\BoykovDocs-QA\after\instructions'
$registryPath = 'C:\BoykovDocs-QA\after\instruction-taxonomy.json'
$reportPath = Join-Path 'C:\BoykovDocs-QA' ('acceptance-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))

node server/scripts/checkInstructionTaxonomyAcceptance.js `
  --directory $snapshotPath `
  --registry $registryPath `
  --origin https://boykovdocs.ru `
  --output-dir $reportPath
```

`--origin` — ожидаемый публичный адрес сайта, используемый для URL и canonical.
`--registry` — именно проверяемый runtime JSON. Если указанный файл отсутствует или повреждён,
проверка должна завершиться ошибкой: подмена его исходным справочником недопустима.
Без `--registry` проверяется **seed из текущего кода**, а не автоматически найденное рабочее
состояние. Такой отчёт подтверждает проект справочника; он не подтверждает фактическую
публикацию, назначения и SEO-настройки рабочего сайта.

Добавьте сравнение с исходным снимком, чтобы проверить сохранность старых инструкций:

```powershell
$baselinePath = 'C:\BoykovDocs-QA\before\instructions'
$reportPath = Join-Path 'C:\BoykovDocs-QA' ('preservation-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))

node server/scripts/checkInstructionTaxonomyAcceptance.js `
  --directory $snapshotPath `
  --registry $registryPath `
  --baseline-directory $baselinePath `
  --origin https://boykovdocs.ru `
  --output-dir $reportPath
```

Сравнение выявляет исчезнувшие документы и изменения защищаемых полей. Из сравнения JSON
исключены только `primaryCategoryId`, `tagIds`, `taxonomyMeta` и `revision`: эти поля могут
измениться при подтверждённом переносе. Все остальные поля защищены сравнением и контрольной
суммой, включая текст, прежний URL, SEO, ссылку на файл и даты. Допустимые отдельные правки
этих полей также появятся в отчёте и требуют объяснения. Байты самих файлов скачивания
этим сравнением не проверяются. Без исходного снимка отсутствие потерь не доказано.

## Проверка работающего сайта

Добавьте `--http-origin` для фактических GET-запросов. Проверка направляет запросы на этот
адрес, а ожидаемые публичные canonical и URL продолжает определять через `--origin`.
Тестовый сайт должен использовать согласованные с этими настройками данные и адреса.

```powershell
$reportPath = Join-Path 'C:\BoykovDocs-QA' ('http-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))

node server/scripts/checkInstructionTaxonomyAcceptance.js `
  --directory $snapshotPath `
  --registry $registryPath `
  --baseline-directory $baselinePath `
  --origin https://boykovdocs.ru `
  --http-origin https://staging.example.ru `
  --output-dir $reportPath
```

HTTP-режим сверяет ответы, HTML и sitemap со снимком: доступность страниц, canonical, robots,
H1, ссылки и перенаправления. Проверяются локальные ссылки структуры и инструкций из просмотренных
страниц; это не обход всего сайта или внешних ресурсов. Переходы HTTP за пределы проверяемого
origin не выполняются, а внешний canonical отмечается предупреждением. Ожидаемые canonical
и URL sitemap сравниваются с `--origin`, даже когда запросы направлены на `--http-origin`.

GET-запросы выполняются последовательно; стандартный предел — 20 000 запросов,
тайм-аут каждого — 10 секунд. Большая проверка может занять значительное время.
Проверьте в отчёте полноту обхода и ошибки запросов. Расхождение может означать ошибку сайта
или несоответствие данных снимку; прежде чем менять код, проверьте дату снимка и версию
развёртывания. Результаты снимка без `--http-origin` являются проверкой модели, а не подтверждением
HTTP, Nginx или итогового HTML. HTTP-проверка не выполняет JavaScript и не заменяет браузерную
проверку React, адаптивности и мобильных экранов.

## Как читать результат

В новой папке сохраняются:

| Файл               | Содержимое                                                                   |
| ------------------ | ---------------------------------------------------------------------------- |
| `acceptance.json`  | Полный отчёт снимка, замечания и результаты сравнения сохранности            |
| `urls.csv`         | Страницы, редиректы и технические варианты URL; UTF-8 с BOM, разделитель `;` |
| `report.md`        | Сводка для чтения и дальнейшей приёмки                                       |
| `http-report.json` | Результат фактических запросов, если задан `--http-origin`                   |

Входные данные не изменяются. Папка результата создаётся новой; существующий результат
не перезаписывается. Сохраните её вне снимков и каталога реестра.

Коды завершения: `0` — нет замечаний уровня error, предупреждения допустимы;
`1` — найдены ошибки проверки; `2` — некорректные входы или ошибка, не позволившая завершить
проверку. В PowerShell код доступен в `$LASTEXITCODE`. Код `0` не означает готовность
к публикации: незавершённые редакторские задачи и ручные проверки оцениваются отдельно.

Сначала проверьте состав входов и область проверки. Отделяйте ошибки от ожидаемо закрытых
страниц и от задач подготовки содержимого.

| Состояние                                  | Ожидаемое поведение                                                     |
| ------------------------------------------ | ----------------------------------------------------------------------- |
| ROOT в черновике                           | Прежний общий каталог остаётся доступным по адресу без завершающего `/` |
| Черновик раздела/тега                      | Публично закрыт; не входит в навигацию и sitemap                        |
| Раздел под черновым каталогом              | Публично закрыт независимо от собственного статуса                      |
| H01 и его разделы                          | Маршрут заблокирован до согласования; это незавершённая публикация      |
| Опубликованная noindex-страница            | Доступна и может быть связана ссылками, в sitemap не входит             |
| Пустая опубликованная страница             | Noindex, без sitemap                                                    |
| Альтернативный canonical                   | Noindex, без sitemap; проверьте целесообразность такого canonical       |
| Пагинация, поиск, сортировка и параметры   | Noindex, canonical базовой страницы                                     |
| Исторический адрес опубликованной страницы | 301 сразу на текущий URL, без цикла                                     |
| Исторический адрес черновой цели           | Закрыт вместе с целью                                                   |
| Опубликованная noindex-инструкция          | Может входить в тематический список, но не в sitemap инструкций         |

Отсутствующие SEO-поля и повторяющиеся заголовки требуют редакторской оценки. Отчёт не пишет
SEO-тексты и не включает индексацию автоматически. Исходные 2 каталога, 52 раздела и 79 тегов
не являются верхним ограничением: дополнительные элементы после согласованного расширения допустимы.

Количество 2 169 относится к исходному распределению. Реальную полноту проверяйте по своему
снимку и отчёту сопоставления CSV. Само наличие этих строк в исходном файле не доказывает
наличие соответствующих инструкций на сайте. 63 спорных исходных назначения должны оставаться
в отдельном списке до индивидуального экспертного решения.

## Ручная приёмка

После устранения замечаний проверьте в тестовой среде:

1. Desktop, планшет и телефон: вкладки админки, длинные названия, карточки, меню и таблицы.
2. Переходы React без перезагрузки: общий каталог → раздел → инструкция → главная.
   H1, canonical, robots, SEO и JSON-LD должны соответствовать текущей странице.
3. Поиск, сортировку и несколько страниц списка; переход по ссылкам пагинации и возврат назад.
4. Ссылки разделов и тегов, хлебные крошки и похожие материалы, включая черновые и noindex-цели.
5. Создание временного раздела/тега, сохранённый предпросмотр, публикацию и снятие с публикации.
   Анонимный и обычный пользователь не должны получать административный предпросмотр.
6. Старые инструкции: URL, текст, SEO, скачивание/PDF, счётчик доступных загрузок и покупку
   по существующему сценарию. Проверку платежей выполняйте по принятой тестовой процедуре.
7. CSV на копии данных: предпросмотр, исключённые строки, применение, журнал, предпросмотр
   отката и откат. Отдельно подтвердите сохранность более поздней правки текста при откате.
8. Свежую полную резервную копию и проверяемый способ восстановления. Manifest проекта покрывает
   `server/src/data` и `server/data`; сохранность `uploads` подтвердите отдельно.

Приложите к приёмке отчёты фактического импорта, список исключённых строк, результаты этой
проверки и отметки ручных проверок. Отчёт на seed или синтетических данных не подтверждает
проверку production, применение импорта, наличие рабочей резервной копии либо успешный откат
на VPS. Сохранённые отчёты могут содержать внутренние ID и URL; не коммитьте рабочие данные
и отчёты с ними в репозиторий.

Общий порядок действий в админке: [инструкция администратора](instruction-taxonomy-administrator.md).
