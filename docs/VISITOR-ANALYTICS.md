# Собственная посещаемость BoykovDocs

Счётчик предназначен для собственной оперативной статистики. Его показатели
не являются копией Яндекс Метрики и не подтверждают, что каждый браузер — человек.

## Сбор

- React и старый статический загрузчик используют один модуль
  `/assets/visitor-tracking.js?v=traffic-filtering` и один экземпляр на документ.
- Просмотр — открытие видимой страницы верхнего уровня. Изменение `q`, фильтров,
  UTM и якоря не считается новым просмотром. Смена пути, страницы пагинации
  `page` и отдельная перезагрузка считаются.
- `navigator.webdriver`, пререндеринг, известные User-Agent роботов и инструментов
  автоматизации не учитываются. Скрытый документ ждёт появления на экране.
- Сервер принимает JSON-запрос с контекстом своего origin. Запросы без браузерного
  контекста, межсайтовые запросы и запросы администратора игнорируются.
- Перед событием браузер получает краткоживущую подписанную квитанцию через
  `/api/visitor-stats/session`. Только квитанция, выданная этому origin, допускает
  запись. Старый публичный payload с одним произвольным `visitorId` больше не
  создаёт запись.
- Подписанная HttpOnly SameSite cookie сохраняет существующий хеш идентификатора
  браузера даже при смене значения localStorage. Срок cookie — год, квитанции —
  15 минут. Подписи разделены по назначению; используется уже настроенный
  `JWT_SECRET`. Новые секреты и изменения `.env` не требуются.
- Отсутствие cookie не запрещает подписанную квитанцию: браузеры с ограничениями
  хранилища не исключаются автоматически. Это ограничивает устойчивость к
  целенаправленной автоматизации, которая умеет имитировать браузерный протокол.
- Повтор доставки использует тот же event ID. Сервер не добавляет повторную
  запись в течение 48 часов, включая перезапуск. Дедупликация при чтении журнала
  и в агенте Boykov Services также защищает агрегаты от повторных v2 event ID.
- Ограничение журнала дедупликации в памяти — 100 000 событий за 48 часов.
  При достижении лимита новые события временно не учитываются; приложение
  продолжает обслуживать посетителей.

## Данные и история

Журнал `server/src/data/analytics/visitor-events.jsonl` дополняется, а не заменяется.
Новые строки содержат `schema: 2`, время, московский день, хеш браузера и хеш event ID.
URL, поисковый запрос, IP, User-Agent, имя и email в журнал не записываются.

Исторические строки содержат только время и хеш браузера. Нельзя достоверно
определить задним числом, какие из них относятся к людям, роботам или изменениям
поиска. Старые данные сохраняются в итогах с явной пометкой. `filteredSince`
обозначает первое записанное событие v2, а не доказательство отсутствия всех ботов.

В админке посетители, визиты и просмотры разделены. Визит начинается после
30 минут без просмотров. Календарные периоды считаются по Москве; «24 часа» —
скользящее окно завершённых минут, как у агента Boykov Services.

## Публикация

Сначала локальные проверки и GitHub PR/Quality Gate, затем merge, затем сервер.
Нужно обновить и собрать клиент и API вместе: старый клиент без квитанций сервер
намеренно не учитывает. Новый публичный модуль нужно разместить до публикации
нового клиентского entrypoint. Обновление Boykov Services обратно совместимо
с журналом прежнего формата. Данные пользователей, покупок и настроек не меняются.

Проверки: `npm run quality:check`; целевые сценарии —
`node --test server/tests/visitor-analytics.test.js`.
