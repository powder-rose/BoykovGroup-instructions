# Данные компании и персональные PDF

В личном кабинете `/account/` появился раздел **Данные компании**. Пользователь может сохранить название организации, ИНН, должность и ФИО руководителя, должность и ФИО ответственного по охране труда. Все шесть полей необязательны; данные можно изменить или очистить в любой момент.

После регистрации через обычную форму или окно скачивания PDF предлагается заполнить анкету. Её можно пропустить. Предложение не мешает подтверждению почты, а форма всегда остаётся доступной в кабинете. Действующие пользователи заполняют её в кабинете без повторной регистрации.

Форма сообщает, что реквизиты используются в скачиваемых инструкциях и при сохранении передаются команде БОЙКОВГРУПП. ИНН, если указан, должен состоять из 10 или 12 цифр. Проверка контрольной суммы не выполняется. Лимиты: название компании — 300 символов, должности и ФИО — по 200.

## Формат документа

При каждом скачивании PDF из каталога или оплаченного заказа сервер подставляет **текущие данные аккаунта**, который скачивает документ:

- Вверху по центру: название компании и ИНН через запятую. Руководитель в шапке не дублируется.
- Ниже в правой половине страницы, с общим левым краем: **УТВЕРЖДАЮ**, отдельной строкой должность руководителя из анкеты, затем линия подписи и ФИО руководителя. Название поля «Должность руководителя» в PDF не печатается. Если должность не заполнена, остаётся строка для заполнения вручную. Длинные должности и ФИО переносятся внутри своих строк и колонок.
- Дата скачивания: `ДД.ММ.ГГГГ`, часовой пояс Москвы.
- После основного текста: должность ответственного слева, линия подписи и ФИО справа. Подпись сохраняется единым блоком при переносе страницы.

Пустые значения оставляют строки для заполнения вручную. PDF администратора также содержит пустой шаблон. Общие инструкции, их история, SEO-данные и JSON оплаченного заказа не получают реквизиты компании. Веб-вступление и послесловие по-прежнему не входят в PDF.

Из скачиваемых PDF исключается точная шаблонная фраза «Настоящая инструкция устанавливает требования безопасности при выполнении работ.», в том числе с переносами строк. Содержательные варианты с указанием конкретных работ сохраняются. Исходные записи инструкций не перезаписываются.

Скачивание из каталога требует подтверждённой почты пользователя либо входа администратора. PDF оплаченного заказа доступен только владельцу заказа; прежний порядок доступа сохранён. Ответы с реквизитами и PDF используют приватный кэш с `no-store`.

## API и хранение

Все операции требуют Bearer-токен действующего пользовательского аккаунта. Профиль недоступен администратору, гостю и удалённому аккаунту. ID пользователя определяется сервером из авторизации.

| Метод  | Адрес                                  | Назначение                                               |
| ------ | -------------------------------------- | -------------------------------------------------------- |
| `GET`  | `/api/account/company-profile`         | Получить свои данные и даты сохранения/завершения анкеты |
| `PUT`  | `/api/account/company-profile`         | Сохранить `{ "companyProfile": { ... } }`                |
| `POST` | `/api/account/company-profile/dismiss` | Пропустить предложение, не меняя реквизиты               |

Имена полей: `companyName`, `inn`, `headPosition`, `headFullName`, `occupationalSafetyPosition`, `occupationalSafetyFullName`. PUT заменяет все шесть полей; отсутствующее поле считается пустым. Ответ содержит `companyProfile`, `updatedAt`, `onboardingCompletedAt`. Ошибка валидации возвращает HTTP 400 и `field` для подсветки поля. Неизвестные поля игнорируются при чтении и сохранении. Сохранённая должность руководителя подставляется в форму, PDF и уведомления. Профили без этого поля возвращают пустую должность.

Профили и очередь писем сохраняются атомарно в `server/data/company-profiles.json`, права файла — `0600`. Файл и временные записи исключены из Git. Используется существующий постоянный том `./app/server/data:/app/data`; новый том и миграция старых инструкций не нужны. Хранилище рассчитано на один процесс API, как и остальные файловые хранилища проекта.

Резервное копирование дополнено каталогом `server/data`, поэтому сохраняет аккаунты, реквизиты и неотправленные уведомления. Отсутствие этого каталога допустимо при первой установке; отсутствие обязательного `server/src/data` остаётся ошибкой. Архив создаётся с правами `0600`.

## Уведомления на почту

После фактического изменения данных письмо с таблицей реквизитов, контактами аккаунта и датой сохранения отправляется на `bd@boykovdocs.ru`. Адрес можно изменить через `COMPANY_PROFILE_NOTIFICATION_TO` в `server/.env`. Используются уже настроенные `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASS`, `SMTP_FROM`.

Первое пустое сохранение, пропуск и сохранение без изменений не отправляют письмо. Очистка ранее заполненных реквизитов отправляет уведомление об изменении. Сбой SMTP не отменяет сохранение анкеты: письмо остаётся в очереди и повторяется с интервалом от минуты до часа. Для одного пользователя сохраняется порядок уведомлений.

Отправка ограничена десятью секундами с закрытием SMTP-соединения. При graceful shutdown завершается текущая попытка; остальные события остаются до следующего запуска. При аварии между приёмом письма почтовым сервером и подтверждением в очереди возможен повтор; у события сохраняется постоянный `Message-ID`.

## Локальная проверка и выпуск

Запустите `npm run dev:server` и `npm run dev:client` в отдельных терминалах. Личный кабинет теперь доступен и через Vite: `http://localhost:5173/account/`. Серверная конфигурация авторизации остаётся прежней: случайный `JWT_SECRET`, `ADMIN_LOGIN`, `ADMIN_PASSWORD_HASH`, `CLIENT_ORIGIN`.

Для ручной проверки: зарегистрируйтесь, заполните часть анкеты или пропустите её, откройте кабинет, измените реквизиты и скачайте инструкцию после подтверждения почты. Проверьте письмо и повторное скачивание с изменёнными данными. Локальный запуск с рабочими SMTP-реквизитами действительно отправляет письма; автоматические тесты используют изолированные данные и локальный тестовый SMTP.

Перед выпуском выполните `npm run quality:check`. Обновите checkout, соберите клиент и перенесите ресурсы из `client/dist` в существующий `public_html` вместе с обновлённым `index.html`. В сборку входят новые `/assets/company-profile-form.js` и `.css`; не удаляйте их при копировании. Файлы `public_html/account/index.html` и `account-20260930.js` обновляются из Git. Пересоберите и пересоздайте сервис `api` обычной командой Compose: очередь учитывает имеющийся graceful shutdown. Изменять маршруты nginx не требуется.
