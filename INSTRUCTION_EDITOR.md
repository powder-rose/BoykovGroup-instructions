# Редактор инструкций

В административной панели раздел **Инструкции** позволяет создавать документы вручную, открывать опубликованные инструкции и продолжать серверные черновики. Кнопка редактирования существующей инструкции открывает тот же редактор. Импорт файлов и текста, автоматическая генерация и платные заказы сохраняют прежние сценарии.

## Содержимое страницы

1. **Заголовок страницы (H1)** — название инструкции.
2. **URL инструкции** — адрес после `/instrukciya-po-ohrane-truda/`. Внутренний ID документа сохраняется при смене адреса. Старые опубликованные адреса перенаправляются на актуальный.
3. **Короткое вступление** — пояснение перед документом на сайте.
4. **Основная инструкция** — форматируемый текст, списки, ссылки и таблицы. Заголовки H2/H3 формируют содержание с переходами. Под документом расположена кнопка PDF.
5. **Разъяснения после инструкции** — отдельный форматируемый текст. Поле необязательное.
6. **SEO Title / SEO Description** — метаданные страницы, одинаковые в серверном HTML и браузере.

Похожие инструкции подбираются автоматически из опубликованного каталога. В PDF входят заголовок и основной документ; веб-вступление и пояснения остаются на странице сайта. Действующее условие скачивания сохраняется: администратор либо зарегистрированный пользователь с подтверждённой почтой.

## Черновики и публикация

- **Предпросмотр** показывает текущие поля без публикации.
- **Сохранить черновик** записывает рабочую версию на сервер. Если инструкция уже опубликована, посетители продолжают видеть прежнюю версию.
- **Опубликовать / Опубликовать изменения** переносит рабочую версию в публичный каталог.
- **Удалить серверный черновик** убирает рабочую версию, сохраняя опубликованную.
- **Снять с публикации** сохраняет инструкцию как черновик и закрывает её публичные страницу, API и PDF.
- Локальные изменения дополнительно сохраняются в браузере отдельно для нового документа и каждого ID. Восстановление предлагается явно.
- Параллельные изменения проверяются по `revision`; устаревшая форма получает конфликт вместо перезаписи новой версии.
- История опубликованных документов и откат сохраняются. При наличии серверного черновика сначала нужно решить, сохранять ли его.

## Совместимость и хранение

Опубликованные документы остаются в `server/src/data/instructions/`. Черновики хранятся отдельно в `server/src/data/instruction-drafts/` и недоступны публичному поиску, PDF и подбору готовой инструкции для платного заказа. Оба каталога находятся на существующем постоянном томе и входят в резервное копирование `server/src/data`.

Старые `intro` и `sections` преобразуются в формат редактора при открытии. Новое поле `instructionContent` является источником основного документа; совместимое представление `intro/sections` сохраняется для прежних потребителей. Веб-поля `webIntro` и `explanationContent` не смешиваются с документом.

Редактор проверяет структуру Tiptap JSON, разрешённые типы ссылок и размеры содержимого. Произвольный HTML не исполняется.

Отдельный раздел статей и `/stati` удалены. Runtime-файл прежних статей не удаляется автоматически.

## Локальный запуск

В `server/.env` нужны случайный `JWT_SECRET`, `ADMIN_LOGIN`, `ADMIN_PASSWORD_HASH` и `CLIENT_ORIGIN=http://localhost:5173`. Запустите `npm run dev:server` и `npm run dev:client` в разных терминалах. Vite передаёт `/api` на `http://127.0.0.1:4000`; при нестандартном адресе можно задать `VITE_API_BASE_URL` в `client/.env.development.local`.

Общий модуль `server/src/shared/instructionDocument.js` используется API и включается в клиентскую сборку. Поэтому при сборке клиента в Docker нужно монтировать весь checkout, а не только `client`:

```bash
docker run --rm -v "$PWD:/work" -w /work/client node:22-bookworm-slim sh -c 'npm ci && npm run build'
```

Для выпуска требуется обновить ресурсы и `index.html` в существующем `public_html`, сохранив служебные файлы сайта, и пересобрать Compose-сервис `api`. Перезапуск nginx и изменение его маршрутов не требуются.
